# Agent 云主机保留与 Credits 计费 · 精简 PRD

日期：2026-11-10

范围：汇总本次会话的生命周期、展示、保留策略与计费更新。当前为前端原型，真实云主机与扣费服务待接入。

## 1. 目标

Agent 从「运行—删除」升级为「运行—休眠—回收」。保留云主机中的文件、依赖和配置，方便继续任务；让用户明确保留会消耗 Credits，并可调整回收时间。面向用户统一使用「云主机」，替代 Sandbox／沙箱等术语。

## 2. 生命周期与保留策略

| 规则 | 要求 |
| --- | --- |
| 运行 → 休眠 | 启动后进入运行；执行任务期间不休眠。执行结束、暂停或等待用户后，连续空闲 1min 进入休眠 |
| 休眠 → 回收 | 默认休眠 10min 后回收；可选 20min、1h、永久保留 |
| 计时起点 | 从每次进入休眠时起算；修改策略不重新计时。唤醒后结束本轮计时，下次休眠重新起算 |
| 永久保留 | 关闭自动回收，仍可休眠；不代表免费，具体计费规则待确认 |
| 缩短保留时间 | 若已超过新时限，提示将立即回收，确认后执行；取消保留原策略 |
| 自动继续任务 | 发送任意非空指令后，休眠状态自动唤醒，已回收状态自动创建新云主机，并执行同一条 query，无需重新发送 |

仅输入草稿、查看信息或调整策略不触发唤醒。准备期间保留 query、显示进度并防止重复提交；不提供独立的手动唤醒／重建按钮。

## 3. 工作台功能列表

| 功能 | 要求 |
| --- | --- |
| 云主机入口 | 右上角终止按钮替换为云主机图标，点击打开「任务云主机」浮层，集中展示状态与操作 |
| 状态与回收时间 | 主行显示「云主机运行中 [10min 后回收 ▾]」；运行中展示所选策略，休眠后展示剩余时间 |
| 回收策略选择 | 点击回收时间，选择 10min／20min／1h／永久保留；菜单标题为「休眠后保留时间」；唤醒／创建中禁用，已回收隐藏 |
| 时长弱展示 | 运行与保留时长使用灰色小字，仅显示 min／h／d，不显示秒；运行时长累计实际执行时间，保留时长自当前云主机创建起算，回收后冻结、重建后重计；展示时长不直接作为已确认的计费时长 |
| 临近回收提醒 | 剩余分钟向上取整；不足一分钟显示「<1min 后回收」，入口与回收选项以琥珀色提醒 |
| 保留说明 | 标题后的 ⓘ 悬浮或聚焦时显示「保留任务云主机中的文件、依赖和配置，方便继续任务。」 |
| 冗余信息移除 | 移除独立倒计时卡片、预计回收时间、横向状态条及底部常驻唤醒／计时解释 |

## 4. Credits 功能列表

| 功能 | 要求 |
| --- | --- |
| 消耗明细入口 | 点击顶部 Credits 总数打开当前任务消耗明细 |
| 任务执行计费项 | 展示模型与工具调用的累计消耗 |
| 云主机保留计费项 | 保留文件、依赖和配置会产生 Credits 消耗；「云主机保留」项常驻，暂无消耗时显示 0 Credits |
| 累计消耗汇总 | 总数 = 任务执行消耗 + 云主机保留消耗；顶部总数与明细同步 |
| 历史消耗保留 | 休眠、唤醒、永久保留、回收或重建均不清空本任务累计消耗，回收后仍显示计费项与历史金额 |
| 计费说明 | 展示「云主机保留会消耗 Credits，回收后保留已产生的消耗记录。」 |
| 计费 Mock | 任务执行 1,250 + 保留 12 = 1,262 Credits；切换保留消耗为 0 后，总数为 1,250；仅用于展示，不代表费率、不随时间累加、不实际扣费 |

## 5. Mock 与验收

| 覆盖范围 | 验收要求 |
| --- | --- |
| 七种展示情形 | 运行中、已休眠、即将回收、永久保留、唤醒中、创建中、已回收；其中永久保留为策略、即将回收为休眠提示 |
| 保留操作 | 四种策略可切换；缩短至已超时时需确认；打开菜单不重置计时 |
| 自动继续 | 休眠／回收后提交 query，准备完成后仅执行一次 |
| 消耗一致性 | 0 消耗及已回收状态均显示「云主机保留」；明细之和等于顶部总数 |
| 可用性 | 支持键盘操作、关闭后焦点恢复及窄屏展示；时长不出现秒级单位 |

状态 Mock：`/mock/cloud-host-states`，时间固定、支持重置。工作台演示入口带 `sandboxDemo=1`，可切换云主机状态和保留消耗示例。演示控件不属于正式产品。

## 6. 上线前待确认

- **费率与计费范围：** 单价、计费起止时点、运行／空闲／休眠／启动是否收费及各状态费率、是否有免费额度、永久保留权限与计费规则。此次仅确认「保留产生消耗」，不据此推定所有状态统一收费。
- **扣费机制：** 计费粒度、金额精度、舍入、扣费周期、延迟结算与余额不足时的处理；由服务端提供消耗记录，避免重复扣费。
- **服务与数据：** 状态、策略与累计消耗持久化；明确文件／依赖／配置保留范围及回收后的数据处理。创建、唤醒或策略保存失败时保留 query／原策略并支持重试。

当前原型刷新或离开任务会重置模拟状态，不能作为生产计费与持久化实现。
